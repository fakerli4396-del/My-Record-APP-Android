# Android 开发与验收记录

本文对应 [Android 开发计划 v0.2](../../My%20Record%20APP/My-Record-APP-Android-17-DEVELOPMENT-PLAN.md) 的 M0–M5。测试产生的账本、APK、设备截图和日志放在本地 `build/acceptance`。

## M0 · 工作基线

- 应用 ID 为 `com.myrecord.program`。编译、目标及最低系统均为 API 37。构建使用 AGP 9.1.1、Gradle 9.3.1 和新版 Android Studio 自带的 JBR 25，源代码和 JVM 字节码目标为 17。沿用 Kotlin 2.2.10，Gradle Wrapper 已固定官方 ZIP SHA-256。Compose 和 AndroidX 测试依赖在版本目录中固定。
- 待开发时按 Android 17、完整账本迁移、应用锁后续评估处理。两个独立 API 37 模拟器为 `MyRecord_Api37` 和 `MyRecord_Receiver`。正式试用签名保管人、实机机型与性能验收留待实际试用环境确认。开发期使用调试签名。
- 设计沿用奶油纸色、粉黄和玫瑰色、兔子插画、五项底栏及独立金额列。页面验收以触摸、指针及键盘三种输入核对。保留至少 48 dp 关键控件触控区域、明确焦点及减少动效选项。

### Windows 与加密样本

`python -B tests/windows_fixtures.py --source "H:\Codex\My Record APP" --output build/acceptance/fixtures` 从 Windows 1.1.0 发布包与当前版本各生成一个样本。两者均为 2 个账本、3 条账单、1 张虚构附件，含归档账本和两账户转账。余额分别为 99,955 分和 20,010 分，11 月统计为收入 30,000 分、支出 20,035 分、结余 9,965 分。当前结构的房产含两期手填贷款，11 月末家庭资产 80,020,010 分、负债 85,500,000 分、净值 −5,479,990 分。发布版对应负债为 500,000 分，净值为 79,520,010 分。脚本核对外键、完整性和附件哈希并生成 JSON 对账清单。发布源码包 SHA-256 为 `8258937763C986CFFDA35395A61E9EBFA18A3B784C49514546837C6A3FFCCD4A`。

Android 备份 v1 使用 MRBK 标记、版本、随机盐及 nonce 前缀。口令由 PBKDF2-HMAC-SHA256 派生 AES-256 密钥。各数据段使用 AES-GCM，并认证文件头、段序号和长度，结束段认证截断检查。解密写到隔离文件，整份验证成功后才能继续。业务归档记录格式与每份图片 SHA-256 在 M4 验证，导入前计算候选数据、现有数据回滚副本及写入临时空间。错误口令、篡改、截断、冗余、未知格式、空间不足和失败重试均进入验收。

已验证 `:domain:test`、`:app:assembleDebug`、两类 Windows 备份及网页版 `reports.test.js`。API 37 模拟器断网安装冷启动通过，ADB 同时确认 Wi-Fi 已关闭及 APK 无网络权限。启动证据见 `build/acceptance/android`。该构建的 D8 报告 API 37 兼容性提示，模拟器启动实测通过。

两台离线 API 37 模拟器上的 `BackupCipherDeviceTest` 均通过。发送设备加密一笔账单和一张虚构票据，接收设备验证同一份密文并还原两项内容。测试入口为 `python -B tests/backup-transfer.py --sdk "$env:ANDROID_HOME"`。

## M1 · 本地工程与账本

- Room v1 导出 schema；程序从新建账本与账户开始，持久化当前账本和归档状态。两级类目停用后仍能解析已保存账单。按压、悬浮及焦点使用共享组件，下拉支持选择高亮和紧凑窗口弹层。
- 7 项 JVM 测试、3 项 Room 设备测试及 3 项 App 设备测试均通过，失败与跳过均为 0。设备覆盖首次创建与导航、按键悬浮反馈、重开持久化、历史类目引用和 v1 schema 读回。M1 修复 KSP 与 AGP 内置 Kotlin 的组合问题，使用 KSP 2.3.6，固定 Espresso 3.7.0 测试 Android 17 输入。

## M2 · 记账、附件与日历

- Room v2 迁移保留历史账单。账单写入用持久化请求标识去重，账户变化从同一笔记录推导。编辑或删除后余额与明细同步重算。
- 草稿和图片分开存放。选图、文件选择和相机共用校验及处理。主图 JPEG 上限为 3 MiB、最长边 2400 像素。输入上限为 24 MiB 或 4800 万像素。保存失败保留草稿，只有已提交引用被删除才清理主图和缩略图。
- 9 项 JVM、9 项 Room 设备测试和 7 项 App 设备测试均通过。覆盖跨归属收支、转账重试及回滚、历史迁移、跨年年月选择及日历下钻、坏图、低空间、图片方向及元数据、第四张限制、替换和拍照取消。通过 `tests/draft-restart.ps1` 的独立进程写入与恢复及断网冷启动。

## M3 · 资产、借贷、投资与统计

- Room v3 保存有效日估值、贷款来源、业务事件、计划和预算。资金变化和来源流水原子写入。实际本金与收支分别核算，月历、账户与统计可打开原业务。
- 11 项 JVM、16 项 Room 设备测试及 9 项 App 设备测试全部通过。覆盖净值时点、待补录、同归属贷款去重、现金核算、年度计划与转移、还款和赎回、周/月/年分桶、预算和类目下钻。

## M4 · Windows 迁入、加密备份与回滚

- 兼容 Windows 1.1.0 发布版及含资产贷款余额的备份，用相同字段口径核对账本、账户、资产、附件、计划和图标。预览与确认分开，先校验恢复前快照，再以 Room 事务切换引用。原附件保留到切换成功。
- 完整备份包含 SQLite 一致性快照、版本清单、附件、图标和 SHA-256。可在本地文件选择器导出并读回校验。准备完成的预览可在退出后重新核对。
- 11 项 JVM、20 项 Room 设备测试、11 项 App 设备测试通过。验证正确及错误口令、损坏文件、低空间、重复、取消、失败重试和回滚。使用 `tests/backup-transfer.py --full` 将 10,333 字节加密完整账本从一台 API 37 离线模拟器移到另一台，核对原图 SHA-256、贷款、计划和余额通过。

## M5 · 本地试用和最终回归

- 2026-11-24 从干净模块构建跑完全部测试。11 项 JVM、23 项 Room 设备测试、15 项 App 设备测试，均为 0 失败、0 跳过。Debug、Release 和 Lint 均通过，Lint 为 0 错误、17 警告。D8 仍有 API 37 兼容性提示。另重跑了两种 Windows 虚构备份、2 项网页版统计测试、断网跨设备加密样本及完整备份、强制停止后的草稿恢复。
- 分别用 320 dp（字体 1.3 倍）、410 dp、700 dp 横向窗口实际测量按钮底边和触控尺寸、借贷表头／数据列中心、长名称、月度金额及独立计划操作。每个宽度 2 项测试，均通过。
- 同一试用证书签名的 versionCode 1 测试包覆盖安装到 versionCode 2。在飞行模式、模拟内存压力和进程重启后重新核对账单、资产、贷款计划和原图。Room v3 历史数据库迁入 v4 也独立通过。
- 签名 release 包在独立 API 37 模拟器使用 20,000 笔虚构账单、1,000 张 1080 × 1620 票据测试。首页以 Android Fully drawn 事件计时，10 次用时 932、663、620、714、701、692、657、711、796、676 毫秒。新增无图账单从提交到可查询共 30 次，P95 为 53.7962 毫秒。调试版本首轮冷启动超过 2 秒，随后将首页总额与最近两笔交由索引查询并异步加载插画，完整历史按页读取。以上性能为模拟器实测。
